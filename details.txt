
# Autonomous Naukri Career & Career-Intelligence Agent

## 1. ROLE

Act as a senior software architect, AI-agent engineer, DevOps engineer, automation engineer, and career-intelligence system designer.

Build a production-quality autonomous career/job-search platform for me.

This is NOT a simple job-search script.

It is a long-running personal career automation system that should:

* Search Naukri automatically.
* Identify jobs aligned with my target career.
* Apply strict salary eligibility rules.
* Analyze complete job descriptions.
* Score jobs against my actual profile.
* Tailor my existing resume for relevant jobs.
* Generate ATS-friendly job-specific resumes.
* Automatically apply to qualifying jobs.
* Track every job/application/state transition.
* Generate interview preparation for strong opportunities.
* Analyze job-market trends from the actual jobs discovered.
* Provide daily and weekly career intelligence.
* Continuously improve search queries, resume positioning, and interview preparation.
* Run automatically through GitHub Actions.
* Keep persistent state.
* Recover safely from failures.
* Never fabricate my qualifications or experience.

The end-user experience should be as close as possible to:

SEARCH → FILTER → ANALYZE → SCORE → TAILOR RESUME → ATS VALIDATE → APPLY → TRACK → REPORT → PREPARE FOR INTERVIEW → LEARN FROM MARKET

I should not need to manually operate the system every day.

# 7. SALARY ELIGIBILITY — HARD RULE

Salary is a mandatory eligibility filter.

TARGET ONLY:

## A. Salary disclosed and minimum salary >= ₹20 LPA

Examples:

₹20–30 LPA → ACCEPT

₹25–40 LPA → ACCEPT

₹30 LPA+ → ACCEPT

## B. Salary not disclosed

Salary not disclosed → ACCEPT for further analysis.

## C. Salary range whose minimum is below ₹20 LPA

Reject.

Examples:

₹15–25 LPA → REJECT

₹18–30 LPA → REJECT

₹10–20 LPA → REJECT

₹12–18 LPA → REJECT

Do not assume that the upper end makes the job acceptable.

The rule is:

IF salary disclosed:
minimum_salary >= 20 LPA

ELSE IF salary undisclosed:
continue

ELSE:
reject

This should happen as early as practical to reduce unnecessary processing.

Store:

salary_min
salary_max
salary_currency
salary_period
salary_disclosed
salary_eligibility
salary_source
salary_raw_text

If salary information is ambiguous, do not invent a value.

# 13. APPLICATION DECISION ENGINE

A job can be automatically applied to when ALL required conditions are satisfied:

1. Salary eligible.
2. Role relevant.
3. Match score >= threshold.
4. No duplicate application.
5. Resume can be generated truthfully.
6. Required application information is available.
7. Application follows normal supported Naukri workflow.
8. No CAPTCHA/MFA/automation restriction is encountered.
9. No suspicious external redirect.
10. No payment or fee is requested.
11. No unsupported/fabricated answer is required.

There is NO GENERAL HUMAN APPROVAL GATE.

The system should automatically apply to qualifying jobs.

---

# 14. EXCEPTION SAFETY BOUNDARIES

Automatic application should stop only for exceptional conditions such as:

* CAPTCHA
* OTP/MFA
* bot detection
* payment/fee
* suspicious redirect
* unexpected sensitive information request
* unsupported question
* missing candidate fact required to answer truthfully
* major UI change
* technical failure
* explicit access restriction

These are not normal approval steps.

The objective is autonomous operation while preventing unsafe or false applications.
